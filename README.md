# Умный термостат с PID + Feedforward и онлайн-оценкой теплопотерь

Прототип на Arduino, реализующий терморегуляцию нагревательной пластины
с компенсацией внешних теплопотерь. Кейсовое задание "Сопряжённая
разработка программного и аппаратного обеспечения".

## Идея проекта

Классический PID реагирует на ошибку *после* того, как она возникла.
Если температура на улице резко падает, пластина сначала остывает —
и только потом PID начинает компенсировать. Feedforward-составляющая
предсказывает эти теплопотери заранее по физической модели и
компенсирует их превентивно.

Дополнительно коэффициент теплопотерь **не задаётся вручную**, а
оценивается в реальном времени рекурсивной линейной регрессией (RLS) —
система самонастраивается под фактические условия (изоляция, обдув и т.д.).

## Архитектура

```
src/
  Sensor.h          — DS18B20: асинхронный опрос, EMA-фильтр, отказоустойчивость
  PIDController.h   — ПИД с анти-виндапом + автонастройка (Ziegler-Nichols)
  ThermalModel.h    — модель теплового баланса + онлайн-регрессия Kloss
  Thermostat.h       — state machine (BOOT/HEATING/STABILIZED/ERROR), интеграция
  thermostat_main.ino — точка входа
simulation/
  diagram.json      — схема для симуляции в Wokwi
  wokwi.toml
data/
  analyze_log.py    — сравнение теории и эксперимента, графики
docs/
  schema.png        — принципиальная электрическая схема
  report.pdf        — презентация проекта
```

## Физическая модель

Тепловой баланс пластины:

```
C * dT/dt = P_heater - Kloss * (T_plate - T_outdoor)
```

В установившемся режиме (dT/dt = 0):

```
P_heater = Kloss * (T_plate - T_outdoor)
```

Отсюда feedforward-член в регуляторе: `FF = Kloss_estimated * (setpoint - T_outdoor)`.

`Kloss_estimated` оценивается онлайн через рекурсивный МНК по наблюдаемым
парам (ΔT, PWM) в моменты, когда система находится в установившемся режиме.

## Конечный автомат

```
BOOT → HEATING ⇄ STABILIZED
  ↑         ↓
  └── ERROR (любой из датчиков отказал) ──┘
```

- **ERROR** всегда переводит актуатор в безопасное состояние (PWM = 0).
- Регрессия Kloss обновляется **только** в STABILIZED (когда dT/dt ≈ 0),
  чтобы не искажать оценку переходным процессом.

## Аппаратная часть

| Компонент       | Пин | Назначение                  |
|-----------------|-----|------------------------------|
| DS18B20 #1      | D2  | Температура пластины         |
| DS18B20 #2      | D3  | Температура улицы (внешняя)  |
| MOSFET/LED      | D6  | ШИМ-управление нагревателем   |

Подтягивающие резисторы 4.7 кОм на линиях DQ обоих датчиков.

## Почему DS18B20

- Цифровой интерфейс (1-Wire) — устойчивость к наводкам по сравнению с
  аналоговым термистором/термопарой на длинных проводах.
- Точность ±0.5°C в рабочем диапазоне — достаточно для тепловой инерции пластины.
- Настраиваемое разрешение (9-12 бит) — компромисс между точностью и
  временем/энергией на конверсию (используется для энергооптимизации:
  датчик улицы работает на 9 битах, т.к. высокая точность внешней
  температуры не требуется).

## Энергооптимизация

1. Асинхронный (неблокирующий) опрос датчиков через `setWaitForConversion(false)`
   вместо `delay(750ms)` — процессор не простаивает в ожидании конверсии.
2. Пониженное разрешение датчика улицы (9 бит, ~94 мс вместо 750 мс) —
   меньше время активности сенсора.
3. Предложение для ESP32: между циклами опроса (500 мс) переводить
   МК в `light sleep` (`esp_sleep_enable_timer_wakeup` + `esp_light_sleep_start()`),
   просыпаясь по таймеру — не реализовано на Arduino Uno (нет соответствующего
   API), но архитектурно `Thermostat::update()` уже неблокирующий и
   совместим с таким переходом.
4. Ограничение скорости нарастания ШИМ (rate limiting) снижает
   переключательные потери в силовом ключе.

## Симуляция без физической платы

Проект настроен для запуска в [Wokwi](https://wokwi.com):
1. Создать новый проект Arduino Uno.
2. Загрузить `src/thermostat_main.ino` + все `.h`-файлы.
3. Импортировать `simulation/diagram.json` как схему.
4. Запустить — в Wokwi можно вручную двигать ползунок температуры
   каждого DS18B20, имитируя изменение погоды на улице, и наблюдать
   реакцию feedforward-составляющей в Serial Plotter.

## Сравнение теории и эксперимента

`data/analyze_log.py` читает CSV-телеметрию (выводится в Serial в формате
`time_ms,setpoint,plate_temp,outdoor_temp,pwm,state,est_kloss`) и строит:
- графики температур и ШИМ во времени,
- диаграмму рассеяния PWM(ΔT) в стабильном режиме с наложенной теоретической
  прямой `PWM = Kloss * ΔT`, вычисляя RMSE отклонения теории от эксперимента.

## Автонастройка PID

`PIDController::autotuneStep()` реализует релейный метод автонастройки
(упрощённый Ziegler-Nichols): система переключает актуатор между 0 и
фиксированной амплитудой, измеряет период и амплитуду возникающих
автоколебаний, и по классическим формулам вычисляет Kp, Ki, Kd.

## Как запустить локально (без Wokwi)

Через Arduino CLI:
```bash
arduino-cli compile --fqbn arduino:avr:uno src/
arduino-cli upload -p /dev/ttyUSB0 --fqbn arduino:avr:uno src/
```

## как запустить код питона для графики:
```bash
python .\analyze_log.py telemetry.csv
```
